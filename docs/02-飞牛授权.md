# 飞牛应用目录授权

这是整个方案最容易卡住的地方。症状很明确：

```
任务加进去，立刻变「出错」
日志里：file_open (/volN/xxx/yyy.mp4) error: Permission denied
```

## 为什么

飞牛的应用跑在**独立账号**下（比如 qBittorrent 是 `qbittorrent`，uid 往往不是 1000），它只能访问**明确授权**的目录。

默认只授权了应用自己的数据目录（`/vol2/@appdata/qbittorrent`）和共享目录（`/vol2/@appshare/qbittorrent`），你要下到自己的「我的文件」里，必须手动授权。

## 三条铁律

### 1. 授权不继承子目录

给 `/vol3/1000` 授权后，写 `/vol3/1000/电影/xxx.mp4` **依然被拒**。

飞牛的授权是精确匹配，不是递归。必须把**真正要写入的那一级目录**单独加进去。

```
❌ /vol3/1000                     ← 只授权这个，写子目录照样失败
✅ /vol3/1000/电影                 ← 实际写入的目标目录
```

所以如果你的下载目录是 `/vol3/1000/电影/动作片`，那要授权的是最后那一级 `动作片`，不是它的上一级 `电影`。

### 2. `--perm` 传 6，不要传 7

| 传的值 | Web UI 显示 | 实际效果 |
| --- | --- | --- |
| `6` | 「读写」 | ✅ ACL 正常下发 |
| `7` | 裸数字「7」 | ❌ UI 不认识这个值，ACL 不下发，写入仍被拒 |

传 7 的时候 UI 里会看到一行很怪的东西——权限列显示成 `7` 而不是「读写」，和其他条目明显不一样。看到这个就说明值传错了。

### 3. 确认改的是哪个 qBittorrent

飞牛上可能同时存在「应用中心版」和「手动安装版」两个 qBittorrent，各占不同端口。

先确认 MCP 连的那个 WebUI 端口：

```bash
./qb-mcp.sh api "app/preferences" | grep web_ui_port
```

然后确认你在浏览器里打开的是同一个端口。**改错实例的表现就是：改完保存了，但查询后端值没变。**

## 操作步骤

### 查当前授权

```bash
fnos-cli app config auth-paths qbittorrent
```

输出示例：

```json
{
  "list": [
    { "path": "/vol2/@appshare/qbittorrent", "perm": 7, "isEditable": false },
    { "path": "/vol3/1000/电影", "perm": 6, "isEditable": true }
  ]
}
```

`isEditable: false` 的是应用自带的，别动。

### 加授权

```bash
fnos-cli app config set-authorization-path qbittorrent "/vol3/1000/电影" --perm 6 --yes
```

要在同一台机器上操作且已 `login`，或者用带 profile 的包装器：

```bash
fnos.cmd app config set-authorization-path qbittorrent "/vol3/1000/电影" --perm 6 --yes
```

### 验证

1. 再跑一次 `auth-paths`，确认新条目 `perm` 是 6
2. 打开飞牛 Web UI → 应用 → qBittorrent → 可访问的文件，确认显示的是「读写」而不是数字
3. 实际加一个任务试下载，看状态是否 `downloading` 而不是 `error`

## 也可以用界面操作

不想用命令行的话，直接在飞牛界面里点：

**应用中心 → qBittorrent → 设置 → 可访问的文件 → `+ 添加` → 选目录 → 权限选「读写」**

界面操作的好处是不会踩 `--perm` 那个坑，坏处是目录多了要一条条点。

## 批量场景

如果三个硬盘上各有一个电影目录，就得加三条：

```bash
fnos-cli app config set-authorization-path qbittorrent "/vol1/1000/电影" --perm 6 --yes
fnos-cli app config set-authorization-path qbittorrent "/vol2/1000/电影" --perm 6 --yes
fnos-cli app config set-authorization-path qbittorrent "/vol3/1000/电影" --perm 6 --yes
```

统一用 6，不会出现「设了新的、旧的掉级」的问题（那个现象只在 6 和 7 混用时出现）。

## 为什么不用 Docker 挂载

如果你的 qBittorrent 是 Docker 部署的，改 volume 挂载也能解决。

但飞牛原生应用（`docker: false`）没有挂载配置可改，只有「可访问的文件」这一条路。用 `fnos-cli app list` 看 `docker` 字段：

- `"docker": true` → 容器，可以改 volume
- `"docker": false` → 原生应用，走授权路径

## 一个反例

```bash
# 只授权了父目录
fnos-cli app config set-authorization-path qbittorrent "/vol3/1000" --perm 6 --yes

# 加任务到子目录
./qb-mcp.sh add '<MAGNET>' '/vol3/1000/电影'

# 结果：任务状态 error，日志 Permission denied
# 原因：/vol3/1000 的授权管不到 /vol3/1000/电影
```
