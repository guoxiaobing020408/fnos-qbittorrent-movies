# 部署

## 需要什么

| 组件 | 要求 |
| --- | --- |
| NAS / 主机 | 飞牛 fnOS（或其他 Linux NAS） |
| qBittorrent | 5.x（本项目在 5.3.1 上验证） |
| MCP 服务 | `qbittorrent-mcp`，跑在 qBittorrent 同一台机器上 |
| 客户端 | bash + curl + python3（脚本只用标准库，不装第三方包） |

## 关于 MCP 服务：它是 qBittorrent 应用包自带的

`qb-mcp.sh` 说话的对象是一个 **MCP（Model Context Protocol）服务**，作用是把 qBittorrent 的 WebUI API 包成 MCP 工具，让 AI Agent 能调用。

**这个服务不需要你单独安装**——它打包在 [sushazhi/fnos-qbittorrent](https://github.com/sushazhi/fnos-qbittorrent) 这个飞牛应用包里（GPL-2.0，打包者 yukihana），装上应用后进设置页开关就行。

### 先拿到这个应用

| 项目 | 值 |
| --- | --- |
| 项目地址 | https://github.com/sushazhi/fnos-qbittorrent |
| 下载地址 | https://github.com/sushazhi/fnos-qbittorrent/releases |
| 资产命名 | `qbittorrent-<版本>-amd64.fpk` / `-arm64.fpk`（约 40 MB） |
| **国内镜像** | [本仓库 Release](https://github.com/guoxiaobing020408/fnos-qbittorrent-movies/releases/tag/v5.3.1.0-mirror) —— 上游在国内经常拉不动，放了一份 amd64 备份 |
| 许可证 | GPL-2.0 |
| 最低系统 | fnOS 1.2.0401 |

飞牛「应用中心 → 手动安装」选 fpk 装上即可。

> 别装成应用中心里那个 **4.6.11** 版的 qBittorrent——那个**没有 MCP 服务**，本项目的所有命令都会连不上。

### 在应用设置里开启

打开 qBittorrent 应用 → 设置 → **「MCP 服务设置（AI 客户端接入）」**：

| 项目 | 说明 |
| --- | --- |
| 启用 MCP 服务 | 总开关，必须勾上 |
| 允许高危操作 | 勾上才允许删除/停止/开始任务；不勾则 AI 只能查看和添加 |
| 服务端口 | 默认 `8081` |
| Web API Key | `qbt_` 开头的密钥，可复制、可重新生成。这就是客户端配置里的 Bearer token |
| MCP 连接地址 | `http://<你的地址>:8081/mcp` |
| 客户端配置 JSON | 页面直接给出示例，复制粘贴即可 |

### 三个开关的实际影响

| 开关 | 关掉后会发生什么 |
| --- | --- |
| 启用 MCP 服务 | 8081 端口不可达，本项目的所有命令都失效 |
| 允许高危操作 | 添加任务可以，但删除/暂停/开始被拒（`qb_delete_torrents` 等返回错误） |

> **注意**：即便开了「允许高危操作」，`app/setPreferences` 这类**全局安全配置端点仍然被硬性拦截**——这是防止 AI 把 WebUI 的鉴权配置改坏、把人锁在外面。改默认保存路径只能走 WebUI 手动操作。

### 本仓库的边界

| 本仓库负责 | 不负责 |
| --- | --- |
| 怎么调这个服务（`qb-mcp.sh`） | 服务本身怎么实现 |
| 调不通时怎么排查 | 服务有 bug 怎么修 |
| 接口契约的说明 | 服务的发布与版本 |

**换应用包会丢 MCP。** 飞牛应用中心那个 4.6.11 版的 qBittorrent 就没有这个服务，只有手动安装的这个 5.3.1 包带。迁移时记得确认。

### 下面的内容是「接口约定」

如果你手上的服务跟本文档对不上，看这一段判断是"版本差异"还是"协议不符"。

如果你完全没有现成服务，也可以按这个约定自己实现一个——用 FastAPI + MCP SDK，一两百行能搞定。下面列出的是**需要满足的契约**，不是要你照抄某个具体项目。


### 协议要求

- **传输**：Streamable HTTP，只接受 `POST /mcp`
- **Content-Type**：`application/json`
- **Accept**：`application/json, text/event-stream`
- **鉴权**：`Authorization: Bearer <api_key>`
- **协议版本**：握手返回 `2025-03-26`（脚本兼容 `2024-11-05` 请求）

最小握手：

```bash
curl -X POST http://<NAS_IP>:8081/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer <key>" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
        "protocolVersion":"2024-11-05","capabilities":{},
        "clientInfo":{"name":"probe","version":"1.0"}}}'
```

期望返回 `serverInfo.name = "qbittorrent-mcp"`。

### 必须实现的 9 个工具

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `qb_app_info` | 无 | 返回 `qbit_version`、`mcp_server` |
| `qb_global_status` | 无 | 全局速率、连接状态、累计量 |
| `qb_list_torrents` | `filter`/`category`/`tag`/`sort`/`limit` | 任务列表 |
| `qb_torrent_detail` | `hash` | 返回 `{hash, properties:{...}, files:[...]}` |
| `qb_add_torrent` | `urls`(数组)/`savepath`/`category`/`stopped` | 添加任务 |
| `qb_start_torrents` | `hashes` | 开始/恢复 |
| `qb_stop_torrents` | `hashes` | 暂停 |
| `qb_delete_torrents` | `hashes`/`delete_files` | 删除 |
| `qb_api_request` | `path`/`method`/`params` | 原生 API 透传 |

### `qb_api_request` 的实现要点

这是让脚本能绕开封装限制的关键，实现时注意：

1. **GET 一律放行**，参数拼查询串
2. **POST 白名单**：`torrents/add`、`torrents/setLocation`、`torrents/toggleSequentialDownload`、`torrents/addTrackers`、`transfer/setUploadLimit` 等
3. **必须屏蔽**：`auth/*`、`app/setPreferences`——这些能改鉴权和全局配置，让 AI 调等于把锁和钥匙一起交出去

屏蔽时返回明确的中文错误，别静默忽略：

```json
{"error": "端点被禁止透传: /api/v2/app/setPreferences（涉及鉴权或全局安全配置，防止 AI 锁死访问能力）"}
```

> 静默忽略比报错更糟。本项目开发过程中被这一点坑过：`app/setPreferences` 返回了"成功"，但值根本没写进去，排查了很久。

### 会话管理

MCP 规范允许服务端返回 `Mcp-Session-Id`，但**无状态实现更简单也更稳**——每次请求自带 Bearer key，不需要维持会话。本项目脚本按无状态写的。

## 部署方式

### 方式 A：Docker（推荐）

概念上就是个把 qBittorrent WebUI API 转成 MCP 的小服务，随便跑在哪台能访问 qBittorrent 的机器上：

```yaml
services:
  qbittorrent-mcp:
    image: <你的镜像>
    container_name: qbittorrent-mcp
    restart: unless-stopped
    ports:
      - "8081:8081"
    environment:
      - QBIT_URL=http://<qbit_host>:8080
      - QBIT_USERNAME=<user>
      - QBIT_PASSWORD=<pass>
      - MCP_API_KEY=<自己生成一个长随机串>
```

注意 `QBIT_URL` 指 qBittorrent 的 **WebUI 端口**，不是 MCP 端口。

### 方式 B：裸机 systemd

```ini
[Unit]
Description=qBittorrent MCP
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/qbittorrent-mcp/main.py
Environment=QBIT_URL=http://127.0.0.1:8080
Environment=MCP_API_KEY=<key>
Restart=always
User=nobody

[Install]
WantedBy=multi-user.target
```

## 客户端配置

把服务登记到 Agent 的 MCP 配置（本节以 WorkBuddy 的 `~/.workbuddy/mcp.json` 为例，其他 Agent 结构类似）：

```json
{
  "mcpServers": {
    "qbittorrent": {
      "type": "http",
      "url": "http://<NAS_IP>:8081/mcp",
      "headers": {
        "Authorization": "Bearer <MCP_API_KEY>"
      }
    }
  }
}
```

`qb-mcp.sh` 会自动从这里读 `url` 和 `Authorization`，不需要额外配置。

> **密钥不要提交到 Git。** 本项目脚本不内置任何密钥，全部运行时读取。
