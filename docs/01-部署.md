# 部署

## 需要什么

| 组件 | 要求 |
| --- | --- |
| NAS / 主机 | 飞牛 fnOS（或其他 Linux NAS） |
| qBittorrent | 5.x（本项目在 5.3.1 上验证） |
| MCP 服务 | `qbittorrent-mcp`，跑在 qBittorrent 同一台机器上 |
| 客户端 | bash + curl + python3（脚本只用标准库，不装第三方包） |

## 关于 MCP 服务（重点：这是第三方项目）

`qb-mcp.sh` 说话的对象是一个 **MCP（Model Context Protocol）服务**，作用是：把 qBittorrent 的 WebUI API 包成 MCP 工具，让 AI Agent 能调用。

**这个服务不是本仓库的东西。** 实测环境里跑的是 `qbittorrent-mcp 1.0.0`，它是一个独立的第三方服务，本仓库：

- 不包含它的源码
- 不分发它的镜像
- 不维护它、不对它的行为负责
- 无法回答"它从哪下载""怎么部署"——请查它自己的项目文档

本仓库负责的是**客户端这一侧**：`qb-mcp.sh` 怎么跟它对话、遇到问题怎么处理。

### 下面这些是「接口约定」，不是某个项目的文档

如果你手上的服务跟本仓库对不上，看这一段来判断是"版本差异"还是"协议不符"。

如果完全没有现成服务，你也可以按这个约定自己实现一个——用 FastAPI + MCP SDK，一两百行能搞定。下面列出的是**需要满足的契约**，不是要你照抄某个具体项目。


### 协议要求

- **传输**：Streamable HTTP，只接受 `POST /mcp`
- **Content-Type**：`application/json`
- **Accept**：`application/json, text/event-stream`
- **鉴权**：`Authorization: Bearer <api_key>`
- **协议版本**：握手返回 `2025-03-26`（脚本兼容 `2024-11-05` 请求）

最小握手：

```bash
curl -X POST http://<NAS_IP>:8081/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer <key>" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
        "protocolVersion":"2024-11-05","capabilities":{},
        "clientInfo":{"name":"probe","version":"1.0"}}}'
```

期望返回 `serverInfo.name = "qbittorrent-mcp"`。

### 必须实现的 9 个工具

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `qb_app_info` | 无 | 返回 `qbit_version`、`mcp_server` |
| `qb_global_status` | 无 | 全局速率、连接状态、累计量 |
| `qb_list_torrents` | `filter`/`category`/`tag`/`sort`/`limit` | 任务列表 |
| `qb_torrent_detail` | `hash` | 返回 `{hash, properties:{...}, files:[...]}` |
| `qb_add_torrent` | `urls`(数组)/`savepath`/`category`/`stopped` | 添加任务 |
| `qb_start_torrents` | `hashes` | 开始/恢复 |
| `qb_stop_torrents` | `hashes` | 暂停 |
| `qb_delete_torrents` | `hashes`/`delete_files` | 删除 |
| `qb_api_request` | `path`/`method`/`params` | 原生 API 透传 |

### `qb_api_request` 的实现要点

这是让脚本能绕开封装限制的关键，实现时注意：

1. **GET 一律放行**，参数拼查询串
2. **POST 白名单**：`torrents/add`、`torrents/setLocation`、`torrents/toggleSequentialDownload`、`torrents/addTrackers`、`transfer/setUploadLimit` 等
3. **必须屏蔽**：`auth/*`、`app/setPreferences`——这些能改鉴权和全局配置，让 AI 调等于把锁和钥匙一起交出去

屏蔽时返回明确的中文错误，别静默忽略：

```json
{"error": "端点被禁止透传: /api/v2/app/setPreferences（涉及鉴权或全局安全配置，防止 AI 锁死访问能力）"}
```

> 静默忽略比报错更糟。本项目开发过程中被这一点坑过：`app/setPreferences` 返回了"成功"，但值根本没写进去，排查了很久。

### 会话管理

MCP 规范允许服务端返回 `Mcp-Session-Id`，但**无状态实现更简单也更稳**——每次请求自带 Bearer key，不需要维持会话。本项目脚本按无状态写的。

## 部署方式

### 方式 A：Docker（推荐）

概念上就是个把 qBittorrent WebUI API 转成 MCP 的小服务，随便跑在哪台能访问 qBittorrent 的机器上：

```yaml
services:
  qbittorrent-mcp:
    image: <你的镜像>
    container_name: qbittorrent-mcp
    restart: unless-stopped
    ports:
      - "8081:8081"
    environment:
      - QBIT_URL=http://<qbit_host>:8080
      - QBIT_USERNAME=<user>
      - QBIT_PASSWORD=<pass>
      - MCP_API_KEY=<自己生成一个长随机串>
```

注意 `QBIT_URL` 指 qBittorrent 的 **WebUI 端口**，不是 MCP 端口。

### 方式 B：裸机 systemd

```ini
[Unit]
Description=qBittorrent MCP
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/qbittorrent-mcp/main.py
Environment=QBIT_URL=http://127.0.0.1:8080
Environment=MCP_API_KEY=<key>
Restart=always
User=nobody

[Install]
WantedBy=multi-user.target
```

## 客户端配置

把服务登记到 Agent 的 MCP 配置（本节以 WorkBuddy 的 `~/.workbuddy/mcp.json` 为例，其他 Agent 结构类似）：

```json
{
  "mcpServers": {
    "qbittorrent": {
      "type": "http",
      "url": "http://<NAS_IP>:8081/mcp",
      "headers": {
        "Authorization": "Bearer <MCP_API_KEY>"
      }
    }
  }
}
```

`qb-mcp.sh` 会自动从这里读 `url` 和 `Authorization`，不需要额外配置。

> **密钥不要提交到 Git。** 本项目脚本不内置任何密钥，全部运行时读取。
